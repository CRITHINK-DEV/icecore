# Spike S4: what `edr report` reads

**Result.** On 31 Oct 2026, `edr report` from Elementary 0.26.1 ran against a real Elementary schema in the sandbox. It selected from **12 relations** and read **155 columns** from them. Of those relations, 4 can be supplied by icecore core views (spec section 7), each with gaps. The other 8, which describe the project (models, tests, sources and so on) or hold failed rows and source freshness, have no core view.
So compat views over the core views alone **cannot** make `edr report` render. The fallback in spec section 8 applies until Phase 6 adds a node-metadata view and a samples view: compat views serve dashboards, and the report is the Streamlit app.
`edr report` also **writes**: it creates a temporary table in the Elementary schema. Snowflake's documentation says a temporary table needs only USAGE on the schema, not CREATE TABLE. We did not measure this: the probe ran as the schema's owner.

Raw data: `spikes/results/s4.json` (keys `contract`, `types`, `filters`, `reads`, `writes`, `described`, `relation_kinds`, `probe_schema_columns`, `versions`, `edr_run`). The raw queries are in `spikes/results/s4_edr_queries.sql` (41 queries, with the run's schema replaced by `<ELEMENTARY_SCHEMA>`).

## Method

- `integration_tests/elementary_probe/` is a dbt project with two models (`probe_customers`, `probe_orders`), one Elementary test (`elementary.volume_anomalies`), and dbt tests that include a warning. Its `generate_schema_name` sends every model, Elementary's included, to one schema, `ICECORE_SANDBOX.ELEMENTARY_PROBE_<run_id>`. The test fixture drops that schema at the end, including on failure.
- `tests/spikes/test_s4_edr_contract.py` runs `dbt deps`, `dbt run --select elementary`, `dbt build`, then `edr report`. Each profile has its own per-run `query_tag`. The test finds edr's 14 sessions with `QUERY_HISTORY_BY_USER` filtered on the tag, because other agents share the user. It then reads each session with `QUERY_HISTORY_BY_SESSION`.
- `analyze_edr_queries` parses every query with sqlglot. It expands stars from `INFORMATION_SCHEMA.COLUMNS` and prunes projections that nothing uses, so `select * from t` inside a CTE counts only the columns the query goes on to use. All 15 queries that read these relations parsed (`parse_fallbacks: 0`, which the test asserts), so the column lists are exact rather than upper bounds. A WHERE counts as a filter on a relation when one of the relation's columns reaches it unchanged (renames allowed), directly or through CTEs, subqueries and unions. A filter on a computed column is not attributed.
- Drift check: the sandbox test compares `contract`, `types`, `filters`, `described` and `relation_kinds` with the committed `s4.json` and fails on any difference (`ICECORE_S4_RECAPTURE=1` records a new baseline). An offline test replays the committed queries through the analyzer against the committed `probe_schema_columns` and must reproduce `contract`, `types`, `filters` and `reads`; it runs where sqlglot is installed.
- Run it with Elementary in a venv of its own (not in the requirements files):

```bash
cd integration_tests
python3.13 -m venv elementary_probe/.venv
elementary_probe/.venv/bin/pip install -r requirements-elementary.txt pytest
source ~/.snowflake/icecore_ci.env
elementary_probe/.venv/bin/pytest -m sandbox tests/spikes/test_s4_edr_contract.py -v
```

## What edr does besides selecting

| Statement | Count | On | Consequence for compat views |
| --- | --- | --- | --- |
| `SHOW OBJECTS IN <schema>` and `SHOW USER FUNCTIONS IN <schema>` | 16 | the Elementary schema | Views are listed by SHOW OBJECTS, so this works |
| `DESCRIBE TABLE` | 9 | `dbt_exposures`, `dbt_invocations`, `dbt_models`, `dbt_source_freshness_results`, `dbt_sources` | DESCRIBE TABLE also works on a view; the column names must match |
| `CREATE OR REPLACE TEMPORARY TABLE <schema>.ordered_test_results__tmp_<ts> AS ...` | 1 | the Elementary schema | Snowflake documents USAGE on the schema as enough for a temporary table (unmeasured here; the probe role owned the schema). icecore itself still writes nothing |

## Filters edr applies

`--days-back` defaults to 7. edr applies it as a WHERE, either directly on the relation or on a `select *` CTE over it. Query numbers refer to `spikes/results/s4_edr_queries.sql`; `reads` in `s4.json` has the full list.

| Relation | Filter (as captured) | Filtered in | Read unfiltered in |
| --- | --- | --- | --- |
| `elementary_test_results` | `DATEDIFF(DAY, CAST(detected_at AS TIMESTAMP), CURRENT_TIMESTAMP()) < 7` | [3] | [33] |
| `dbt_run_results` | `DATEDIFF(DAY, CAST(execute_completed_at AS TIMESTAMP), CURRENT_TIMESTAMP()) < 7` | [3] | [37], [41] |
| `model_run_results` | `DATEDIFF(DAY, CAST(generated_at AS TIMESTAMP), CURRENT_TIMESTAMP()) < 7 AND NOT unique_id LIKE 'model.elementary.%'`, applied on the CTE `model_runs` | [27] | none |
| `dbt_source_freshness_results` | `DATEDIFF(DAY, CAST(generated_at AS TIMESTAMP), CURRENT_TIMESTAMP()) < 7` | [8] | none |
| `test_result_rows` | `DATEDIFF(DAY, CAST(detected_at AS TIMESTAMP), CURRENT_TIMESTAMP()) < 7 AND elementary_test_results_id IN (ids of the latest invocation in edr's temporary table)` | [5] | none |
| `dbt_models` | `package_name <> 'elementary'` | [16], [36] | [3], [33], [37], [41] |
| `dbt_tests` | `type = 'singular'` | [26] | [3], [30], [33] |

Five relations get the 7-day window. `dbt_invocations` [41], `dbt_sources`, `dbt_seeds`, `dbt_snapshots` and `dbt_exposures` are never filtered.
The filters cast the TEXT timestamps with `CAST(... AS TIMESTAMP)`, so compat views must emit strings that Snowflake can cast.

## Mapping to icecore core views (spec section 7)

| Elementary relation | icecore core view | Columns the core view cannot supply today |
| --- | --- | --- |
| `dbt_invocations` | `invocations` (`invocation_id`, `command`) | `full_refresh`, `selected`, `job_id`, `job_name`, `job_run_id`, `job_run_url`, `job_url`, `orchestrator` (null is acceptable for the job_* and orchestrator fields; `full_refresh` and `selected` need `dbt.*` attributes) |
| `dbt_run_results` | `node_executions` (`invocation_id`, `unique_id`, `execution_time` from `execution_time_s`) | `generated_at`, `execute_completed_at` (need span end times exposed as text), `model_execution_id` (can be built as invocation_id + unique_id) |
| `model_run_results` | `node_executions` where type = model | `compiled_code`, `full_refresh`, `generated_at`, `name`, `schema_name` |
| `elementary_test_results` | `test_results` (+ `metrics` for anomaly tests) | `id`, `detected_at` as TIMESTAMP_NTZ, `test_execution_id`, `database_name`, `schema_name`, `table_name`, `test_sub_type`, `test_results_description`, `test_results_query`, `other`, `owners`, `tags`, `result_rows`, `test_params` |
| `test_result_rows` | **unsupported**: failed-row samples are emitted (`dbt.sample.*`) but no core view exposes them | needs a samples view |
| `dbt_models`, `dbt_tests`, `dbt_sources`, `dbt_seeds`, `dbt_snapshots`, `dbt_exposures` | **unsupported**: no core view holds manifest metadata (description, tags, meta, owner, path, alias, materialization, test params); `lineage` has edges only (`depends_on_nodes` can come from it) | needs a node-metadata view from a manifest emission |
| `dbt_source_freshness_results` | **unsupported** until S3 confirms the hook fires for `dbt source freshness` | |

## Consequences for Phase 6

1. For `edr report` to render, icecore must add two views: a node-metadata view (manifest emission per node) and a samples view. Without them, the compat views serve dashboards only.
2. Compat views must reproduce Elementary's types exactly: TEXT timestamps that Snowflake can cast, and TEXT JSON fields. The contract above, captured from 0.26.1, is the target (see UC8).
3. `edr report` creates a temporary table in the schema it reads. Snowflake documents USAGE on the schema as enough for that, but this is unmeasured. Phase 6 should verify it with a role that only has USAGE and SELECT on the compat schema, and document the result.
