# Spike S4: what `edr report` reads

**Status: blocked, contract not captured yet.** The capture test needs Elementary to write its own tables
into a schema `ICECORE_SANDBOX.ELEMENTARY_PROBE_<run_id>`, which the test drops at the end. Role
`ICECORE_CI` cannot create that schema: it only owns `SPIKES`. Snowflake returns
`Your primary role ICECORE_CI must have CREATE SCHEMA granted on DATABASE ICECORE_SANDBOX`.
Asked on the story on 31 Oct 2026. Fix: `GRANT CREATE SCHEMA ON DATABASE ICECORE_SANDBOX TO ROLE ICECORE_CI;`
Then run the test below. It writes `spikes/results/s4.json` and `spikes/results/s4_edr_queries.sql`,
and the captured contract replaces the provisional table in this note.

## Versions

| Component | Version |
| --- | --- |
| Elementary CLI | `elementary-data 0.26.1` (`elementary-data[snowflake]`) |
| Elementary dbt package | `elementary-data/elementary 0.26.1` (pinned in `integration_tests/elementary_probe/packages.yml`; the CLI's internal project requires this same version) |
| dbt (probe venv) | dbt-core 1.12.6, dbt-snowflake 1.12.4 |

The compatibility target is pinned to these Elementary versions in `macros/compat/ELEMENTARY_VERSION` (UC8). The CLI requirement is `integration_tests/requirements-elementary.txt`.

## Method

- `integration_tests/elementary_probe/` is a dbt project with two models (`probe_customers`, `probe_orders`), one Elementary test (`elementary.volume_anomalies`), and dbt tests that include a warning. Its `generate_schema_name` sends every model, Elementary's included, to the target schema `ELEMENTARY_PROBE_<run_id>`.
- `tests/spikes/test_s4_edr_contract.py` runs `dbt deps`, `dbt run --select elementary`, `dbt build`, then `edr report`. Both profiles carry a per-run `query_tag`. The test finds edr's sessions with `QUERY_HISTORY_BY_USER` filtered on that tag; other agents share the user. It then reads each session with `QUERY_HISTORY_BY_SESSION`. `capture_edr_contract(sf, session_id)` keeps the relations of the `ELEMENTARY_PROBE_*` schema. It resolves columns with sqlglot's qualifier, which also expands stars. When a query does not parse, it falls back to the relation's known columns that appear as words in the query, which gives an upper bound.
- Elementary is installed in its own venv, not in the requirements files:

```bash
cd integration_tests
python3.13 -m venv elementary_probe/.venv
elementary_probe/.venv/bin/pip install -r requirements-elementary.txt pytest
source ~/.snowflake/icecore_ci.env
elementary_probe/.venv/bin/pytest -m sandbox tests/spikes/test_s4_edr_contract.py -v
```
